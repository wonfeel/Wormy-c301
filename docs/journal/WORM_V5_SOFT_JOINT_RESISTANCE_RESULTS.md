## 2. Реализация

### 2.1. `WormBody` (body.hpp/body.cpp)

Два новых приватных поля (`joint_soft_saturation_`, `joint_stiffening_gain_`,
оба дефолт `0.0f`) и два новых публичных сеттера
(`set_joint_soft_saturation`, `set_joint_stiffening_gain`), ровно в стиле
уже существующих (`set_bend_stiffness`, `set_joint_angle_clamp`).

`WormBody::step()`'s кламп-строка (была `angles_[i] = std::clamp(angles_[i],
-joint_angle_clamp_, joint_angle_clamp_);`) заменена на трёхветочную логику:

```cpp
constexpr float kJointHardSafetyLimit = 1.2f;
if (joint_soft_saturation_ > 0.0f) {
    // Механизм 1: гладкое насыщение, c = joint_angle_clamp_ (номинальный
    // масштаб, не жёсткая стена).
    const float satScale = std::max(1e-6f, joint_angle_clamp_);
    angles_[i] = satScale * std::tanh(angles_[i] / satScale);
    angles_[i] = std::clamp(angles_[i], -kJointHardSafetyLimit, kJointHardSafetyLimit);
} else if (joint_stiffening_gain_ > 0.0f) {
    // Механизм 2: маленький жёсткий кламп joint_angle_clamp_ ОБХОДИТСЯ -
    // равновесие задаёт k_soft против привода, не внешний потолок. Только
    // большой предохранитель.
    angles_[i] = std::clamp(angles_[i], -kJointHardSafetyLimit, kJointHardSafetyLimit);
} else {
    // Дефолт (оба тумблера выключены): побитово прежний жёсткий кламп.
    angles_[i] = std::clamp(angles_[i], -joint_angle_clamp_, joint_angle_clamp_);
}
```

`kJointHardSafetyLimit=1.2` - ТА ЖЕ величина, что этот же комментарий
`body.cpp` называет причиной катастрофического "узла", когда она была
ПЕРВИЧНЫМ клампом; здесь - чисто численный предохранитель (в точной
арифметике `c*tanh(x/c)` уже строго внутри `(-c,c)`, так что для механизма 1
этот предохранитель практически никогда не должен срабатывать - подтверждено
ниже, раздел 5: 0.00% сэмплов у обоих `tanh`-точек касаются даже старого
0.25-эталона, не то что 1.2).

Кубический член механизма 2 добавлен В ОТДЕЛЬНОМ месте - СРАЗУ после
pose-decay (leaky-интегратора), ДО клампа/насыщения, как явно требовало
задание ("add a cubic restoring term to the accumulation BEFORE any clamp"):

```cpp
if (joint_stiffening_gain_ > 0.0f) {
    const float a = angles_[i];
    angles_[i] += -joint_stiffening_gain_ * a * a * a * dt;
}
```

Оба тумблера дефолтятся в `0.0f` - при обоих выключенных срабатывает третья
(`else`) ветка, побитово идентичная старому хардклампу; это подтверждено
`ctest` ниже (раздел 3).

### 4.1. Механизм 1 (tanh-насыщение) - убирает пиннинг, но НЕ помогает форме/эффективности

`peakBendAmp` для (b)/(c) - **НЕ клампCAT** (0.1162 при c=0.25, вместо
0.25; 0.2166 при c=0.5, вместо 0.5) - механизм реально нашёл sub-ceiling
равновесие, не пиннинг. Но это равновесие оказалось НИЖЕ, чем то, что давал
жёсткий кламп (0.1162/0.2166 против REF's 0.2500), а не выше, как можно было
бы наивно надеяться от "снятия потолка". Причина видна в частоте: freq
выросла в **2.57x** (c=0.25) и **1.60x** (c=0.5) относительно REF -
тот же задокументированный во ВСЕЙ серии `WORM_V5_*.md` паттерн ("energy
goes into frequency, not amplitude", см. `WORM_V5_RESULTS.md` раздел 6) -
здесь он воспроизводится ещё раз, на СОВЕРШЕННО другом рычаге (не
`muscleCalciumTau`/`bodyPoseDecayRate`/`bodyBendStiffness`/
`proprioceptiveOffset`, как в прошлых фазах, а замена самого механизма
клампирования). Путевая эффективность падает на **-47.7%** (c=0.25) и
**-32.0%** (c=0.5) относительно REF - реальная, некошумовая цена.

### 4.2. Механизм 2 (кубическое сопротивление) - Парето-лучше REF по большинству осей

И `k_soft=1.5`, и `k_soft=4.0` дают ЛУЧШУЮ путевую эффективность, чем REF
(+11.4%/+6.4%), и заметно ВЫШЕ пиковую амплитуду сустава, реально
приближаясь (либо перескакивая) к биологической цели (`k_soft=4.0` -
80.7-96.2%, ближе всего изо всех пяти точек этой фазы; `k_soft=1.5` -
121.0-144.2%, перескок). Частота ПАДАЕТ немного (0.0681-0.0798Гц против REF
0.0782Гц) - в противоположность механизму 1, здесь "энергия" явно идёт в
амплитуду, а не в частоту - качественно ДРУГОЕ поведение контура, чем при
tanh-насыщении. Цена - `minCoiledRatio` (запас до узлования) заметно ниже,
чем у REF (`k_soft=1.5`: 0.636 против 0.820, `k_soft=4.0`: 0.791 против
0.820) - монотонно хуже при БОЛЬШЕЙ реализованной амплитуде, ровно тот же
задокументированный компромисс, что уже нашёл `WORM_V5_JOINT_CLAMP_
RESULTS.md` для простого раскрытия клампа (раздел 5.4 того файла) - но
здесь запас (2.1x/2.6x) остаётся дальше от порога отказа (0.30), чем при
клампе=0.6 из того отчёта (1.9x).

### 4.3. Честная оговорка про калибровку `k_soft`

Обоснование выбора `k_soft` (`WormBody::step`'s `d(angle)/dt = drive -
r*angle - k_soft*angle^3`, `r=bodyPoseDecayRate=0.5`): "точка перехода"
(где кубический член сравнивается по величине с линейным затуханием)
`angle_c = sqrt(r/k_soft)`. `k_soft=1.5` даёт `angle_c=sqrt(0.5/1.5)=0.577`
рад - НАРОЧНО выбран близко к ВЕРХНЕЙ границе цели (0.589 рад, Сценарий III
`WORM_V5_REAL_AMPLITUDE_TARGET.md`), в надежде, что сопротивление начнёт
"кусаться" примерно там, где нужно остановиться. `k_soft=4.0` даёт
`angle_c=sqrt(0.5/4.0)=0.354` рад - НАРОЧНО выбран заметно НИЖЕ цели, как
более консервативная, "кусающаяся раньше" альтернатива для сравнения.
**Честно**: этот линейный quasi-static heuristic НЕ предсказал результат
точно - реально достигнутый пик (0.7124 рад при `k_soft=1.5`) оказался
почти на 24% ВЫШЕ, чем сам предполагаемый "переходный" угол 0.577 рад, а
`k_soft=4.0` дал пик 0.4752 рад против предсказанного перехода 0.354 рад
(+34%) - обе точки перескакивают свой собственный "порог перехода" на
заметную величину, ожидаемо: реальный привод НЕ постоянный (осциллирующий,
многочастотный сигнал по всей 24-суставной цепи, не статичный `D`), так что
простая quasi-static оценка равновесия - лишь ГРУБЫЙ ориентир для выбора
порядка величины `k_soft`, не точная формула. Зафиксировано честно, не
скрыто - будущей фазе, если она продолжит эту ось, стоит рассматривать
promежуточные `k_soft` (например, 2.5-3.0) для более точного попадания в
целевой диапазон, если `k_soft=4.0`'s 80.7-96.2% сочтут недостаточно
близким.

### 8.5. Итоговый вердикт и рекомендация

**ЧАСТИЧНО ПОДТВЕРЖДЕНО.** Решающие для отгрузочного решения пункты -
реализация корректна и побитово нейтральна при дефолте (подтверждено),
`ctest`/регрессия проходят один в один (подтверждено), SURVIVAL 48/48 без
единого узла/хлыста на всех пяти точках на независимом сиде (подтверждено),
качественная иерархия "cubic лучше tanh" по форме/эффективности/приближению
к биологической цели (подтверждено с запасом). Единственное, что не
выдержало независимую перепроверку - узкое утверждение "cubic УВЕЛИЧИВАЕТ
число зон изгиба сверх хардклампа" (раздел 5.2) - на независимых сидах это
скорее "cubic держит число зон примерно на уровне хардклампа, не обрушивая
его, как tanh", а не "cubic делает форму заметно лучше хардклампа" в этом
конкретном узком смысле. Это не меняет итоговое ранжирование механизмов
(cubic по-прежнему заметно предпочтительнее tanh по всем осям), но
ослабляет самое оптимистичное прочтение раздела 5.2.

**Есть ли теперь основание шиповать soft-resistance механизм в дефолт? Ещё
нет - но направление cubic-стифининга (НЕ tanh-насыщения) продолжает
выглядеть жизнеспособным кандидатом для ПРОДОЛЖЕНИЯ исследования, не для
немедленной отгрузки.** Конкретно:

- **tanh-насыщение (механизм 1) - закрыть эту ветвь.** Независимая
  перепроверка на двух сидах ТОЛЬКО усиливает исходный вывод отчёта: реальный,
  устойчивый, драматический регресс формы (схлопывание в одну зону) и
  эффективности - не сид-специфичный артефакт, а робастный эффект. Нет
  оснований продолжать эту ветвь.
- **cubic-стифининг (механизм 2), `k_soft` около 4.0 - остаётся ЕДИНСТВЕННЫМ
  жизнеспособным кандидатом для дальнейшей работы, но не готов к отгрузке.**
  SURVIVAL цел с хорошим запасом (2.7x порога на независимом сиде), пиковая
  амплитуда ближе всего к биологической цели (81-97% против 42-51% у
  референса), эффективность реально выше референса на обоих типах измерений
  (+5.4%/+8.8% на моём сиде, +6.4%/+11.4% на сиде отчёта - направление
  устойчиво). НО: (1) узкая метрика "лучше референса по числу зон" не
  подтвердилась - честный текущий вывод "не хуже референса по форме, лучше
  по эффективности/амплитуде", не "лучше по форме"; (2) запас по
  `minCoiledRatio` при `k_soft=1.5` - худший из всех проверенных точек
